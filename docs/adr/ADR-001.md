# ADR-001 — Tecnologia e reúso (Python/Flask, SQLAlchemy, MySQL)

- **Status:** proposto
- **Data:** 14/11/2026
- **Responsável:** Kelvin Fernando
- **Cenários e regras relacionados:** C03, RN01 a RN05

## Contexto
O grupo tem 3 semanas até o incremento 1. Laura domina Flask; Diego domina MySQL; Kelvin domina HTML/CSS/JS (Etapa 1, seção 9). É preciso código-fonte versionado, testes automatizados e CI (plataformas low-code não servem).

## Alternativas consideradas
| Alternativa | Vantagens neste sistema | Desvantagens neste sistema |
|---|---|---|
| Flask + SQLAlchemy + MySQL | Domínio do grupo; micro-framework deixa a estrutura de módulos livre; SQLAlchemy permite trocar o banco (testes em SQLite). | Menos funcionalidades prontas que Django; configuração de MySQL pode dar trabalho (risco já mapeado). |
| Django + MySQL | Admin, autenticação e ORM prontos. | Curva de aprendizado; estrutura imposta pelo framework dificulta separar o domínio; ninguém do grupo domina. |
| Node.js/Express + MySQL | Mesma linguagem do front. | Só Kelvin conhece; Laura e Diego teriam curva de aprendizado. |

## Decisão
Usar Python 3.12 com Flask, SQLAlchemy e PyMySQL; MySQL em execução normal e SQLite em memória nos testes e no pipeline.

| O que melhora | O que piora (trade-off) | O que fica mais difícil de mudar |
|---|---|---|
| Produtividade imediata; testes rápidos e sem servidor de banco no CI. | Diferenças entre SQLite e MySQL podem esconder defeitos (ex.: tipos de data). | Trocar de linguagem/framework depois. |

## Como verificar
O pipeline executa os testes em máquina limpa; um teste de integração contra MySQL real é previsto na Etapa 3.
